# スプライト版：左右端の壁の松明の引き継ぎ

作成日: 2026-11-24

## 状況と目的

arlq-sprites で、ステージの左右の端がどこかを分かりやすくするため、左右の一番端の壁に小さな照明（壁掛けの松明）を付ける。検討だけ済んでいて、まだ実装していない。

見た目だけの要素で、ゲームのルールは変えない。

## 決定事項（ユーザーと合意済み）

- 松明の位置は `Floor.decor` に持たせる。新しい値は `DECOR_WALL_TORCH`。`Floor` に専用の属性は作らない。
- 位置はゲーム開始時に一度だけ決める。プレイ中に壁が変わっても、新しく端になった壁には付け直さない。
- 地形が変わって（壁が壊されて）松明の壁が壁でなくなったら、そのセルの decor も消す。描画側の「壁のときだけ描く」には頼らない。
- 全部の行には付けず、およそ3行に1つにする。

## 仕様

### 端の壁の定義

フィールドの各行 `y` について、次の2つを端の壁とする。

- 左端の壁: その行で一番左にある「壁以外」のセルの、すぐ左のセル。このセルの左はすべて壁で、右は壁以外になる。
- 右端の壁: その行で一番右にある「壁以外」のセルの、すぐ右のセル。このセルの右はすべて壁で、左は壁以外になる。

「壁」の判定は `update_outer_wall_decor()` と同じ `(*d.WALL_CHARS, d.CHAR_HIDDEN_D_GATE)` にする。そうしないと、隠し通路のせいで端の位置がずれる。壁以外のセルがない行には付けない。

### 付ける行

`y % (d.TILE_HEIGHT + 1) in (2, 5)` の行にだけ付ける。`TILE_HEIGHT` は 6 なので、7 で割った余りが 2 か 5 の行になる。

- フィールドは、高さ6の部屋の段と仕切りの行（`y % 7 == 0`）が交互に並んでいる。各段の2行目と5行目に付けるので、1段に左右それぞれ2本、間隔は3〜4行になる。
- 定義をそのまま全行に当てはめると、仕切りの行では「壁以外」のセルが縦の通路だけになる。その結果、外周から遠い内側の壁に松明が付いてしまう（ステージ1の y=7 では x=18）。行を選ぶのはこれを避けるためでもある。
- 定数は `defs.py` に置く（例: `WALL_TORCH_ROW_OFFSETS = (2, 5)`）。
- 乱数は使わない。ゲームの `utils.rand` を使うと、シードとリプレイの再現性が変わってしまう。

ステージ1での配置例（`[`、`]` が松明。壁の凹凸に合わせて x 位置が1〜2マスずれるが、それで構わない）:

```
###########################################################################
##############           ##          #          ##           ##############
############[            #           #           #           ]#############
##############           #           #           #           ##############
##############           #           #           #           ##############
#############[           #           #                       ]#############
##############           #           ##                     ###############
###################   ##########   #######################   ##############
##############           #           ##         ##           ##############
############[            #           #           #           ]#############
```

### 付けないセル

端の壁が次のどれかなら、その行のその側には付けない。

- `CHAR_WALL` 以外のセル。
  - `CHAR_HIDDEN_D_GATE`：付けると隠し通路の場所を教えてしまう。
  - `CHAR_GOLEM_WALL`：開始時にはないはずだが、念のため除く。
- decor がすでに `DECOR_NONE` 以外のセル。

### データの作り方

- `stage_types.Floor` に、松明を置くメソッドを追加する（例: `place_wall_torch_decor()`）。`update_outer_wall_decor()` の隣に置く。
- `game_session.py:61` のループで、`update_outer_wall_decor()` の直後に全フロアに対して呼ぶ。ステージ1〜4、ステージ5、ステージ6の全フロアがここを通る。
- `update_outer_wall_decor()` は、外周と埋もれた壁の decor だけを消して付け直す。decor が空でないセルは上書きしないので、松明の decor は残る。松明の壁は隣が床なので、外周や埋もれた壁にはならない。
- ループの巻き戻しは、`ReplayContext` のスナップショット（`Floor` の pickle）を読み戻す。decor も一緒に戻るので、追加の処理はいらない。
- `stage_replay.py:64` の `restore()` は、巻き戻した後のフロアに、発見済みの隠し要素を戻すだけ。松明を置き直す必要はない。

### 壁が壊れたときの修正

壁が壊れるのは `game_engine.py:183` 付近の1か所で、`sword_break`、`golem_wall_break`、ペガサスでゴーレムの壁を抜けたときにここを通る。今は `broken_walls.add()` のあとに `update_outer_wall_decor()` を呼んでいる。ここで、壊れたセル（`(player.x, player.y)`）の decor が `DECOR_WALL_TORCH` なら `DECOR_NONE` に戻す。

- 処理は、`Floor` のメソッドか `update_outer_wall_decor()` の中にまとめてもよい。`update_outer_wall_decor()` の中にする場合は、「decor が `DECOR_WALL_TORCH` なのにセルが `CHAR_WALL` でない」ものを消す形にする。そうすれば、今後ほかの地形変化が増えても対応できる。
- 消さずに残ると、次の2つがそのセルを「decor あり」として避けてしまう。
  - 宝箱のきらめき（`treasure_particles.sparkle_cells`）
  - ダンジョンコアの左右の括弧表示（`display.core_bracket_is_clear`）
- 新しく端になった壁には付け直さない。

### 既存の decor との関係（確認済み）

- `DECOR_FALLEN_ROCKS`、`DECOR_BOSS_ROUTE*`、`DECOR_BRIDGEHEAD_PREFIX*` は床セルにだけ付く。壁セルの松明とは重ならない。
- `DECOR_OUTER_WALL`、`DECOR_BURIED_WALL` は、周囲8マスがすべて壁のセルにだけ付く。松明の壁とは重ならない。
- ターミナル版（`blessed_funcs.py`）と通常GUI（`pyglet_funcs.py`）は、知らない decor の値を無視する。この2つの表示は変わらない。

### 描画（スプライト版のみ）

`sprites/sprite_terrain.py` の `_draw_tile()` で、壁の柱を描いたあと、decor が `DECOR_WALL_TORCH` なら燭台を描く。decor は `draw_stage(decor=...)` で、すでに sprite 側に渡されている（`self._decor_at()`）。

- 形: 柱の内側（左端の壁なら東、右端の壁なら西）の端に付ける。腕木と小さな炎で、柱の高さの中ほどに描く。今の 60° の視点では柱の側面はほとんど見えないので、柱から少し内側へ張り出した炎として描く。
- 向き: 左右どちらの端かは、隣のセルが壁かどうかで判定する。それで足りないなら、decor の値を左右で分けてもよい（例: `wall torch:east`）。
- レイヤー: その行の `'column'` レイヤーに置く。隣の床にいるキャラクターは前面に描かれる。
- 光: 光は素材の光の画像（炎、光の輪、柱への照り返し）だけにする。隣の床に落ちる光は付けない（ユーザーと合意済み）。
- 見え方:

  | セルの状態 | 表示 |
  | --- | --- |
  | 未探索 | 描かない |
  | 探索済み・視界の外 | 暗くした炎だけ（光なし） |
  | 視界内 | 炎と光 |
  | マップモード | 描かない |

- 素材: 作成済み（`build-walls.py -- --torch`。詳しくは `dev-samples/3d-stage1/README.md`）。壁の部品と同じ 300×500 の画面範囲なので、柱と同じ位置と大きさで重ねればよい。
  - `assets/walls/wall-torch-{east,west}.png`: 金具と柄（炎なし）。通常の合成で、壁と同じ色で着色して重ねる。
  - `assets/walls/wall-torch-{east,west}-light.png`: 炎、光の輪、柱への照り返し。着色せずに加算で重ねる（`GL_SRC_ALPHA, GL_ONE`）。視界外では、明るさを少し下げて加算する。
  - 左端の壁には `east`、右端の壁には `west` を使う。
- 炎の揺らぎ: 任意。最初は静止画にする。待機中のアニメーション（idle bob など）の再描画に乗せられるかは、あとで判断する。

### 対象範囲（ユーザーと合意済み）

1. ステージ5（訓練室、`'training'` テーマ、壁は箱型）には付けない。テーマが `'training'` のとき（`STAGE_TERRAIN_THEMES` で決まる）は描かない。decor は置いても置かなくてもよい。
2. 対象はスプライト版だけにする。ターミナル版と通常GUIの表示は変えない。
3. README には書かない。見た目だけの変化のため。

## テスト

`tests/` にヘッドレスのテストを追加する。

- 生成したステージで、`DECOR_WALL_TORCH` が付いた各セルについて、次を確かめる。
  - `CHAR_WALL` である。
  - 行が `y % 7 in (2, 5)` である。
  - その行の一番左、または一番右の「壁以外」のセルの隣である。
- 松明の壁を剣で壊すと（`sword_break`）、そのセルの decor が `DECOR_NONE` になる。
- 松明を置いても、同じシードで生成したフィールドと敵の配置が変わらない（乱数を使っていない）。

いつもどおり、`pytest`、`python -m compileall src`、`import arlq` を確認する。描画は arlq-sprites を実際に動かして確認する。スクリーンショットは、ゲームのウィンドウだけを撮るか、先にユーザーに確認する。
