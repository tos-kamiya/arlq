# ステージ6のダンジョンコア導入の引き継ぎ

作成日: 2026-11-11

## 状況と目的

ステージ6で魔物が増え続ける理由をストーリー上で説明するため、「ダンジョンコア」を導入する。ここまでの会話では名前・表示・基本仕様を決めただけで、ゲームへの実装は行っていない。

## ストーリー

日本語:

> ダンジョンの奥に「ダンジョンコア」が出現した。ダンジョンコアは膨大な魔力を蓄えた結晶であり、魔物を呼び寄せ、また生み出す。それ自体に攻撃力はないが、周りに集まった多くの魔物によって守られている。
> 王からダンジョンコアの破壊を依頼された冒険者が、前哨基地から討伐に向かう。

English:

> Deep in the dungeon, a Dungeon Core has emerged. This crystal, brimming with vast magical power, draws monsters to it and spawns new ones. The core cannot attack, but it is shielded by the many monsters that gather around it.
> At the king's request, an adventurer sets out from the outpost to destroy it.

## 名前の検討経緯

- 当初案は「魔王の実」。英語の直訳 "Demon King's Fruit" には、JRPG翻訳調であること、所有格のせいで魔王本人がいるように読めること、種子（seed）か実（fruit）かがずれること、という問題があった。
- "Devil Fruit" / "Demon Fruit" は『ONE PIECE』の「悪魔の実」を連想させるため不採用。
- 名前に "seed" を入れると、`--seed` などの乱数シードの用語と README 上で紛らわしい。
- 最終的に「ダンジョンコア / Dungeon Core」に決定した。英語（LitRPG の dungeon core）でも日本語でも「魔物を生み出し、魔物に守られるダンジョンの中枢」として定着しており、設定と合う。植物という設定はなくし、結晶として扱う。
- 『Dungeon Keeper』の "Dungeon Heart" と同じ名前は避ける。

## 決定した仕様

- **表示**: `[*]` の3マス。真ん中の `*` がダンジョンコアの位置（出現位置）。拠点 `/\`（`stage6._place_bridgehead`、2マスの装飾）と同じく、AAで表現する。
  - `[O]` も候補に挙がったが、`O` は崩落（`CHAR_COLLAPSE`）、`o` は妖精と紛らわしいため不採用。
  - `[` `]` `*` はマップ上では未使用（`*` はゲームオーバー画面の印でのみ使用）。
- **出現タイミング**: 最終階のボス `F'`（`STAGE6_BOSS_PARTY` の先頭）を倒すと、その近くに出現する。初期配置はしない。
- **出現距離**: 倒した `F'` の位置から、Vortex の半径のおよそ半分までの距離。Vortex の半径は `stage6._bridgehead_known_radius` と同じく `FIELD_WIDTH * VORTEX_FLOOR_DIAMETER_RATIO / 2` を `FOV_WIDTH_EXPANSION_RATIO` で割った値を基準にし、楕円の範囲（`iterate_ellipse_points` と同じ考え方）で扱う想定。
- **扱い**: 接触すると壊せる、モンスターのようなもの。自身は攻撃しない。
- **撃破後**: ダンジョンコアを倒すと `T`（宝箱）と `M`（ミミック）が出現する。今は `F'` 撃破でこれが起きるが、その間にダンジョンコアの撃破が挟まる形になる。クリア条件は、従来どおり宝箱を取ること。
- **魔物の生成**: 今と同じ（初期スポーンと20ターンごとのスポーン）。コアの有無や位置による生成ルールの変更はしない。

## 現行コードの関連箇所

- `stage6.py` 最終階の生成処理（420〜447行付近）では、`T` と `M` は初期配置済み。`T` は `"T" + F` のキーと `boss_id=1` でロックされ、`M` は `mimic_boss_char=F`、`boss_id=1`、`active=False` で配置されている。
- `arlq.unlock_treasure_for_defeat` と `arlq.activate_mimic_for_defeat` は、倒したモンスターの `boss_id` が一致するとき、宝箱をアンロックし、ミミックを起動する。
- したがって「`T` と `M` が出現する」は、現行コードでは「宝箱のアンロックとミミックの起動」に当たる。これをコア撃破時に移すのか、宝箱やミミックをコア撃破時に新たに配置するのかは、実装時に確認する（下記の未決事項1）。

## 未決事項・実装時に確認すること

1. `T` と `M` について、初期配置のままトリガーだけをコアに移すか、コア撃破時に初めて配置するか。前者のほうが既存の `boss_id` の仕組みを使えるので変更が小さい。`F'` には `boss_id=1` が付いているので、`F'` 撃破でアンロックされないよう、`boss_id` の付け替えが必要。
2. コアのデータ表現。新しい `MonsterTribe` にするか、専用のエンティティにするか。レベル・攻撃力（接触で必ず壊せるなら攻撃力0、レベル1相当など）、経験値の有無、パーティー結合の対象外にすること、`special_monster` の扱い、移動しないことを決める。
3. 3マス表示の当たり判定。当たり判定を `*` の1マスだけにして `[` `]` は通れない装飾にするか、3マスどれに接触しても壊せるようにするか。
4. 出現位置の条件。3マスが横に並んだ床があること、プレイヤーや他のエンティティ・階段・障壁と重ならないこと、到達できること。範囲内に候補がない場合の対処（範囲を広げる、最寄りの点を選ぶなど）。
5. `F'` 撃破と同時に起きる処理（Vortex の効果、パーティー解散など）とコア出現の順番。
6. 表示の対応。blessed、pyglet（テキスト）、スプライト表示（`sprite_funcs.py`）のそれぞれで `[*]` をどう描くか。地図の記憶・視界の外での表示、ステータス画面の強さ一覧（`display.build_strength_column`）に出すか。
7. ストーリー文の表示場所（ステージ開始時の画面、README）。README.md と README-ja_JP.md のステージ6の説明（「最終階の強化ファイアドレイク（`F'`）を倒して宝箱を取るとクリア」）を更新する。
8. 生成乱数の消費が変わるため、既存のシード文字列・トレースとの互換性への影響を確認する。`tests/` にコアの出現・撃破・`T`/`M` のトリガーについてのテストを追加する。

## スプライト版の3Dモデル（試作）

`dev-samples/3d-stage1/build-dungeon-core.py` で作成。形はユーザーの確認済みで、ゲームへの組み込みはまだ。

```bash
DUNGEON_CORE_OUT=<出力先> blender --background --threads 4 --python dev-samples/3d-stage1/build-dungeon-core.py
```

- 中央に、紫がかった透明な大きい八面体の水晶が浮かぶ。中にはアーモンド形の目があり、カメラの方を向く。白目は淡い紫灰色、虹彩は光る赤紫、瞳は黒い縦長のスリット。
- 水晶を中心に、上から見て正方形の柱を4本、十字（前後左右）に立てる。十字全体は、上から見て時計回りに30度回す（`YAW`）。真正面を向かないようにするためと、手前の柱が水晶と目を隠さないようにするため。柱の上面は平らで、材質は磨いた紫がかった黒の石。各面に紫に光る縦の溝、上端と根元の近くに光る帯を入れる。
- 黒っぽい光は、水晶からいろいろな方向へ伸びる四角錐のトゲで表す。中心は黒く、縁は紫で、先ほど薄い。目を隠さないよう、カメラへまっすぐ向かうトゲは除く。
- 台座はなし。
- 柱の並びの横幅を1.7マス（`FRAME_CELLS`）に合わせる。画像は3マス幅（`CELLS`）で、その中央に置く。はみ出しはマスの上へ0.45マス、下へ0.65マス。
- 画像の書き出し先の既定は `src/arlq/assets/dungeon-core/`（`dungeon-core.png` と、`cells`・`under`・`overhang` を書いた `dungeon-core.json`）。ただし、まだ書き出していない。
- 検討の経緯: 自然の岩の柱と岩の台座から始め、四角い柱、上下の梁でつないだ枠、枠を斜めにした形、枠を90度回した形を経て、今の十字の4本柱になった。
