# ステージ1の3Dキャラクター試作

透明感のある樹脂・水晶風の立体駒を、Blender 4.0.2で作成した検討用素材。
採用モデルから透過画像を書き出し、`arlq --sprites` の別GUIで利用する。
ゲームルールは変更せず、元のPyglet GUIも引き続き利用できる。

## スプライト版GUI

```bash
uv run -p .venv/bin/python arlq --sprites
```

全画像を共通の倍率で描き、モデルの足元（地面の原点）がマスの中心に来るように配置する。大きさは3Dモデルの大きさに従う（後述の「かっこよさを強めたリファイン案」を参照）。
マスからのはみ出しを許容し、未作成のキャラクターは文字表示へフォールバックする。
識別・擬態・FOVは元のGUIの判断をそのまま利用する。
強弱・状態の色は、キャラクターが立つ地面に描いた楕円の円盤で示す。円盤は中心ほど濃く、キャラクターから離れるほど透明になる。中心は足元に置き、半径はマス幅の1.3倍。キャラクターと同じ60度の見下ろしに合わせて縦を sin 60° ≈ 0.87倍にし、画像の後ろに描く（`sprite_funcs.py` の `GROUND_DISC_*`）。プレイヤーのLPが減ったときの黄色・赤も、マスの塗りつぶしではなくこの円盤の色で示す。毒状態は、プレイヤーの円盤を対角線で分け、右上半分を紫、左下半分をLPの色にして示す。プレイヤーの画像は変えない。薄表示とマップの白黒表示にも対応する。

壁は、同じ60度の見下ろしで見た高さのあるブロックとして描く。上面を北へ0.25マス持ち上げ（`WALL_OVERHANG`）、すぐ北のマスに張り出させる。南のマスが壁でなければ、持ち上げた分の帯に暗い手前の側面を描く。描画は北の行から南の行へ「その行の壁 → その行のキャラクター」の順にし、壁は北のマスのキャラクターの足元を隠してよいが、南のキャラクターは隠さない。視界の境界線は壁とキャラクターより上に描く。壁の見た目は古代ギリシャ風の大理石の列柱にする（実物とは異なり、各マスに1本ずつ柱を立てる）。
柱身は太く、見える長さは画面範囲の半分以下に抑える。柱頭（梁）と土台は縦に厚くして前の面を帯として見せ、60度の見下ろしで上面が大きくなりすぎないよう奥行きは浅めにする。照明はキャラクターより弱くし、ほぼ白の大理石でも上面・前の面・柱身の陰影が着色後に残るようにする。
`build-walls.py` が同じ60度の平行投影カメラ・同じ画面範囲（1マスと北への張り出し分、260×500ピクセル）で3つの部品を書き出す。

- `wall-column.png`: 土台・柱身・柱頭（外側の輪郭線あり）
- `wall-link-west.png`、`wall-link-east.png`: 西・東の隣のマスも壁のときに描く、梁と土台の半分（輪郭線なし。マスの境目で継ぎ目が出ないようにする）

部品はほぼ白で書き出し、GUIが「見えている・探索済み」の壁の色を、それぞれ2.4倍・1.75倍した色で着色する（`WALL_TINT`）。未探索の隣のマスへはつながない。
南北に並ぶ壁は、南の柱が北の柱の足元に重なって奥へ続く列柱に見える。部品の画像がない場合は図形だけの描画に戻る。

```bash
blender --background --threads 4 --python dev-samples/3d-stage1/build-walls.py -- --save
```

`--save` を付けると `heroic/walls.blend` も保存する。

床は暗い敷石を1マス1枚で敷き、模様が少し違う2種類を市松模様に並べる（(x + y) の偶奇）。
奇数のマスは色もわずかに暗くする（`FLOOR_CHECKER_SHADE`）。
見えている・探索済みの床は、暖かみのある暗い灰色で着色する（`FLOOR_TINTS`）。視界の外の探索済みの範囲は、見えている範囲との違いが分かるよう、床も壁もはっきり暗くする（壁は `WALL_TINT` で、見えている壁は2.4倍、探索済みの壁は1.75倍）。
移動できる範囲の表示、まきびし、柵、未探索の霧は従来の色のまま。

```bash
blender --background --threads 4 --python dev-samples/3d-stage1/build-floor.py
```

`src/arlq/assets/floor/floor-a.png` と `floor-b.png` を出力する。
画像は `src/arlq/assets/characters/` に同梱する。プレイヤーの `@` は画像へ焼き込まず、ステータスや強さの列は従来の文字表示を維持する。

```bash
blender --background --threads 4 --python dev-samples/3d-stage1/export-sprites.py
PYTHONPATH=src .venv/bin/python dev-samples/3d-stage1/preview-sprite-ui.py
```

最初のコマンドは採用した60度カメラ付きモデルから5枚を書き出し、透明な余白を切り詰める。
2番目はコントローラーを使わないヘッドレス描画確認で、`preview-sprite-ui.png` を出力する。

### 輪郭線のみのトゥーン表現

色・材質・透明度・照明・Cyclesの陰影は維持し、Blender Freestyleで輪郭線を合成する。
輪郭と可視の部位の境目を暗い線で描き、稜線の一律描画は無効にする。
256ピクセルのレンダリング時に線幅4ピクセルとし、ゲームサイズに縮小した際にも輪郭を残す。
GUI側の1.8倍表示と強弱・状態の色表示は維持する。

参考: [Shade3Dの輪郭線レンダリングの記事](https://knowledge.shade3d.jp/knowledgebase/%E8%BC%AA%E9%83%AD%E7%B7%9A%E3%82%92%E3%83%AC%E3%83%B3%E3%83%80%E3%83%AA%E3%83%B3%E3%82%B0%E3%81%99%E3%82%8B%EF%BC%88%E3%83%88%E3%82%A5%E3%83%BC%E3%83%B3%E3%83%AC%E3%83%B3%E3%83%80%E3%83%A9-%EF%BC%89) の「フォトリアル（エッジ付）」に相当する方向性。Shade3Dそのものは使用せず、Blenderで実現する。

変更前の5枚は `sprites-before-outline/` に保存している。

## 作成したキャラクター

## かっこよさを強めたリファイン案

`heroic/` は、採用した5体の造形の特徴を維持したまま、見た目の迫力を強めた案。
ステージ1の残りのキメラ `c`、宝箱 `T`、ドラゴン `D` も同じ方針で追加した。
`build-heroic.py` が8体を1つのシーンに新しく作り、スプライト書き出しの中心座標も保存する。

- 共通: 背後からの寒色・暖色のリムライトと、縁が淡く光る材質。色の彩度を上げ、Standard表示で発光色の白飛びを防ぐ。
- アメーバ2種類: アメーバは空色、レアアメーバは橙色の樹脂にする（紫は毒の印象になるため変更）。膜に軽い揺らぎを付け、内部に縦長の瞳を持つ光る核と小さな気泡を追加。周囲の鈍角の円錐6つは維持する。レアアメーバの上部3つの突起は、金色に光る六角の結晶にする。
- バイソン: 肩の大きなこぶを暗い毛の塊で覆い、頭を下げた突進の姿勢にする。太い角は外へ張り出して上へ反り、目は赤く光る。黒い鼻先と蹄、短い尾を追加。
- コモドドラゴン: 吻から尾まで1本の角ばった胴体にし、尾をS字に曲げる。脚は関節で曲げて横へ張り出し、光る金色の目、眉の突起、背の低い淡色の稜線を追加。爪は付けない。
- キメラ `c`: ステージ1で剣を落とすモンスター。小さい画面でも読めるよう、基本はライオンにして細かい造作を減らす。小さめの金色の胴体に、二重の深紅のたてがみと光る目を付け、淡く光る平たい刃の剣を口に横向きにくわえる。尾は太い緑のヘビにして背中の上へ高く持ち上げ、首元を広げたコブラ風の頭、黄色く光る目、赤い舌で目立たせる。ヤギの要素は付けない。
- 宝箱 `T`: 透明感を抑えたマホガニー色の樹脂に、金の帯・角金具・錠前とルビーを付ける。ふたを後ろへ大きく開け、中の金貨と金色の光を見せる。宝箱の表示は開錠後に限られるため、開いた姿にした。宝に擬態した敵も既存の表示判断どおり同じ画像になる。
- ドラゴン `D`: ステージ1のボス。エメラルドの角ばった胴体で首と頭を持ち上げ、尾を後ろで巻く。金の角・背の棘・爪、橙に光る目、少し開いた顎を付ける。半透明の膜を持つ翼は、縦長のマスで小さくならないよう上へ持ち上げて横幅を抑える。モデル自体を大きく作り、翼のはみ出しを許容して胴体を他のキャラクターと同程度の大きさにする。
- ノミコン `n`: 仲間。開いた状態で浮かぶ魔導書。藍色の革表紙に金の角金具、羊皮紙のページに水色に光るルーンの行、赤いしおり。ページを読ませるためカメラ側へ12度傾ける。
- オキュラー `o`: 仲間。浮かぶ大きな眼球。真珠色の白目、橙に光る虹彩と黒い瞳、透明な角膜。ジャイロスコープのような金の輪2本で囲む。視線はカメラ（プレイヤー）へ向ける。
- プレイヤー: 2等身・円筒形の胴体・短い腕・足なし・画面下向きの構成を維持する。結晶の兜に光るバイザーと金の飾り、肩当て、金のベルトを付け、マントを深紅で裾に金の縁取りにする。右手に光る短剣を低く構える。

```bash
blender --background --threads 4 --python dev-samples/3d-stage1/build-heroic.py
blender --background --threads 4 --python dev-samples/3d-stage1/export-sprites.py -- --heroic
PYTHONPATH=src .venv/bin/python dev-samples/3d-stage1/preview-sprite-ui.py
```

1番目は `heroic/characters-angle60.blend` と比較画像 `heroic/preview-angle60.png` を出力する。
2番目はゲーム用の10枚を書き出す。`-- --heroic --only n o` のように文字を並べると、指定したキャラクターだけを書き出す。

モンスター6体（`a` `A` `b` `c` `d` `D`）は、正面から画面左へ30度だけ向きを変えてモデルに適用する（`MONSTER_YAW`）。プレイヤー・宝箱・仲間は正面向きのまま。

スプライトの大きさは3Dモデルの段階で決める。`build-heroic.py` の `SIZES` で各モデルをアメーバ基準の大きさに作り、メッシュへ適用する。
書き出しは全キャラクター共通で2.6単位あたり256ピクセル（撮影範囲4.6単位、453ピクセル四方）でレンダリングし、撮影の中心（足元から0.35単位上）に対して上下・左右対称に余白を切り詰める。足元は画像中心から一定のピクセル数だけ下になり、GUIはこれを `SPRITE_GROUND_OFFSET_PIXELS` として使う。
GUIは全画像を同じ倍率で描く（アメーバの幅186ピクセルがマス幅の1.8倍、`sprite_funcs.py` の `SPRITE_REFERENCE_PIXELS`）。
ドラゴンだけ表示倍率を変える処理はなく、モデルが大きいため画像も大きくなる。外側の輪郭は従来どおり4ピクセル、部位の境目は1.5ピクセルの薄い線にして、細部が多くても線がうるさくならないようにする。サンプル数は256。
リファイン前の5枚は `sprites-before-heroic/` に保存している。

### 仲間の光の柱

仲間（`n` `o`、今後の `p` `l` も同じ）は、モンスターと区別するため薄い緑の光の柱に囲まれて表示する。
柱は画像に焼き込まず、GUIが地面の円盤と同じ楕円を底面とする、上が開いた円筒として描く（`sprite_funcs.py` の `pillar_image()` と `PILLAR_*`）。
奥の面はキャラクターの後ろ、手前の面はキャラクターの上に加算合成で重ね、側面の縁ほど明るく、上へ行くほど薄くする。
柱は仲間の画像がある場合だけ描き、色は仲間の緑（全体表示の薄表示では暗い緑、マップモードでは灰色）。足元の円盤は従来どおり。
プレイヤーに同行中の仲間は、元のGUIではプレイヤーの右隣のマスに文字で描くが、スプライト版では画像がプレイヤーと重なるため、0.6倍の大きさでプレイヤーの右肩のあたりに浮かべ、小さな柱で囲む（`FAMILIAR_*`）。`--heroic` を付けなければ従来の採用モデルから書き出す。
