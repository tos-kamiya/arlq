# ステージ1の3Dキャラクター試作

透明感のある樹脂・水晶風の立体駒を、Blender 4.0.2で作成した検討用素材。
現行モデルから透過画像を書き出し、`arlq --sprites` の別GUIで利用する。
ゲームルールは変更せず、元のPyglet GUIも引き続き利用できる。

## スプライト版GUI

```bash
uv run -p .venv/bin/python arlq --sprites
```

全画像を共通の倍率で描き、モデルの足元（地面の原点）がマスの中心に来るように配置する。大きさは3Dモデルの大きさに従う（現行のキャラクターモデルを参照）。
マスからのはみ出しを許容し、未作成のキャラクターは文字表示へフォールバックする。
識別・擬態・FOVは元のGUIの判断をそのまま利用する。
強弱・状態の色は、キャラクターが立つ地面に描いた楕円の円盤で示す。円盤は中心ほど濃く、キャラクターから離れるほど透明になる。中心は足元に置き、半径はマス幅の1.3倍。キャラクターと同じ60度の見下ろしに合わせて縦を sin 60° ≈ 0.87倍にし、画像の後ろに描く（`sprite_funcs.py` の `GROUND_DISC_*`）。プレイヤーのLPが減ったときの黄色・赤も、マスの塗りつぶしではなくこの円盤の色で示す。毒状態は、プレイヤーの円盤を対角線で分け、右上半分を紫、左下半分をLPの色にして示す。プレイヤーの画像は変えない。倒せる強さのボス（`EFFECT_UNLOCK_TREASURE` を持つ `D` `F`）は、元のGUIでは黄色の文字だが、他の倒せるモンスターと揃えて円盤を青にし、右上半分だけを黄色にする。強いときは他と同じ赤一色。宝箱と宝に擬態した敵は黄色一色のまま。薄表示とマップの白黒表示にも対応する。

壁は、同じ60度の見下ろしで見た高さのあるブロックとして描く。上面を北へ0.25マス持ち上げ（`WALL_OVERHANG`）、すぐ北のマスに張り出させる。南のマスが壁でなければ、持ち上げた分の帯に暗い手前の側面を描く。描画は北の行から南の行へ「その行の壁 → その行のキャラクター」の順にし、壁は北のマスのキャラクターの足元を隠してよいが、南のキャラクターは隠さない。視界の境界線は壁とキャラクターより上に描く。壁の見た目は古代ギリシャ風の大理石の列柱にする（実物とは異なり、各マスに1本ずつ柱を立てる）。
柱身は太く、見える長さは画面範囲の半分以下に抑える。柱頭（梁）と土台は縦に厚くして前の面を帯として見せ、60度の見下ろしで上面が大きくなりすぎないよう奥行きは浅めにする。照明はキャラクターより弱くし、ほぼ白の大理石でも上面・前の面・柱身の陰影が着色後に残るようにする。
`build-walls.py` が同じ60度の平行投影カメラ・同じ画面範囲（1マスと北への張り出し分、260×500ピクセル）で3つの部品を書き出す。

- `wall-column.png`: 土台・柱身・柱頭（外側の輪郭線あり）
- `wall-link-west.png`、`wall-link-east.png`: 西・東の隣のマスも壁のときに描く、梁と土台の半分（輪郭線なし。マスの境目で継ぎ目が出ないようにする）

部品はほぼ白で書き出し、GUIが「見えている・探索済み」の壁の色を、それぞれ2.4倍・1.75倍した色で着色する（`WALL_TINT`）。未探索の隣のマスへはつながない。
南北に並ぶ壁は、南の柱が北の柱の足元に重なって奥へ続く列柱に見える。部品の画像がない場合は図形だけの描画に戻る。

```bash
blender --background --threads 4 --python dev-samples/3d-stage1/build-walls.py
```


床は暗い敷石を1マス1枚で敷き、模様が少し違う2種類を市松模様に並べる（(x + y) の偶奇）。
奇数のマスは色もわずかに暗くする（`FLOOR_CHECKER_SHADE`）。
見えている・探索済みの床は、暖かみのある暗い灰色で着色する（`FLOOR_TINTS`）。視界の外の探索済みの範囲は、見えている範囲との違いが分かるよう、床も壁もはっきり暗くする（壁は `WALL_TINT` で、見えている壁は2.4倍、探索済みの壁は1.75倍）。
移動できる範囲の表示、まきびし、柵、未探索の霧は従来の色のまま。

```bash
blender --background --threads 4 --python dev-samples/3d-stage1/build-floor.py
```

`src/arlq/assets/floor/floor-a.png` と `floor-b.png` を出力する。

階段（`^` と `v`）は、黄色の文字の代わりに大理石の段で描く。`build-stairs.py` が壁と同じ60度の平行投影カメラ・同じ画面範囲（1マスと北への張り出し分、260×500ピクセル）で2枚を書き出し、GUIは壁の部品と同じ位置・大きさで敷石の上に重ねる。

- `stairs-up.png`: 左右に低い側壁のある4段の上り階段。マスの南端近くから北へ上り、最上段は北のマスに少し張り出す（壁の柱と同じ層に描く）
- `stairs-down.png`: 縁石で囲んだ穴の中を南（手前）へ下りる4段の階段。手前へ下りることで蹴上げがカメラを向き、上り階段と同じく暗い帯として段が見える。深い段ほど暗く、底は真っ暗。穴の外の地面はホールドアウトの透明な板で隠す。縁石は青みのある灰色で書き出し、GUIの金色の着色で床に近い暖かい灰色になるようにする（`KERB_COLOR`）

照明は壁と違い、主光源を真上やや奥に置いて、踏み面を明るく、手前を向く蹴上げを暗くして段を読みやすくする。画像はほぼ白で書き出し、GUIが元の黄色の文字に合わせて金色（`STAIR_TINT`）に着色し、視界外の探索済みでは `STAIR_EXPLORED_SHADE` で暗くする。画像がない場合は従来どおり黄色の文字で描く。

```bash
blender --background --threads 4 --python dev-samples/3d-stage1/build-stairs.py
```

`src/arlq/assets/stairs/stairs-up.png` と `stairs-down.png` を出力する。

崩落（Collapse）の穴（`O`）も、黄色の文字の代わりに、敷石が割れて崩れ落ちたぎざぎざの穴として描く。`build-pit.py` が階段と同じカメラ・同じ画面範囲で `pit.png` を書き出し、GUIは階段と同じ位置・大きさ・着色（`TERRAIN_TINT`、`TERRAIN_EXPLORED_SHADE`）で敷石の上に重ねる。穴の縁は不規則な楕円で、その周りの割れた敷石の板が少しずつ違う角度で穴へ傾き、板の間のすき間がひびに見える。穴の中は暗い縦穴で、底は真っ暗、落ちていく小さなかけらが3つある。穴の外の地面はホールドアウトの透明な板で隠す。敷石の板は階段の縁石と同じく青みのある灰色で書き出し、金色の着色で床に近い色になるようにする（`SLAB_COLOR`）。プレイヤーが穴の上に立てるよう、壁の層（キャラクターより奥）に描く。中央の `?`（崩落そのもの）は従来どおり文字。画像がない場合は黄色の `O` の文字で描く。

```bash
blender --background --threads 4 --python dev-samples/3d-stage1/build-pit.py
```

`src/arlq/assets/pit/pit.png` を出力する。

結界（`=`）のマスは、普通の敷石の上で赤い炎が燃えている姿で描く（マス全体を赤い岩にすると溶岩風呂のように見えたため）。炎はBlenderの画像ではなく、GUIが起動時に作る半透明の画像（`sprite_funcs.py` の `flame_image()`、`FLAME_*`）で、マスの下半分（下端から真ん中まで）の5か所から、大きさの違う小さな火が立ち上る。火はしずく形で、根元は丸く明るい橙、先は細く深い赤、根元の周りに柔らかい光のにじみがある。火の配置が違う2通りを市松模様に置き、背の高い火は北のマスに少しかかる。加算合成で床に重ね、キャラクターより奥に描く。動きはない。視界外の探索済みのマスは `FLAME_EXPLORED_SHADE` で暗くする。守りのお守りで結界に入っても体力を失わない間は、プレイヤーを中心にした周り1マス（自分と周りの8マス）だけ、炎の代わりに同じ形の薄い灰色の煙（`smoke_image()`、`SMOKE_*`）を描き、それより遠いマスは燃えたまま。別のフロアを見ている間は煙にしない。スプライト版では赤い `=` の文字は描かない（元のGUIと端末版は従来どおり）。
画像は `src/arlq/assets/characters/` に同梱する。プレイヤーの `@` は画像へ焼き込まず、ステータスや強さの列は従来の文字表示を維持する。

```bash
blender --background --threads 4 --python dev-samples/3d-stage1/export-sprites.py
PYTHONPATH=src .venv/bin/python dev-samples/3d-stage1/preview-sprite-ui.py
```

最初のコマンドは `heroic/characters-angle60.blend` からゲーム用のキャラクター画像を書き出し、透明な余白を切り詰める。
2番目はコントローラーを使わないヘッドレス描画確認で、`preview-sprite-ui.png` を出力する。

### 輪郭線のみのトゥーン表現

色・材質・透明度・照明・Cyclesの陰影は維持し、Blender Freestyleで輪郭線を合成する。
輪郭と可視の部位の境目を暗い線で描き、稜線の一律描画は無効にする。
256ピクセルのレンダリング時に線幅4ピクセルとし、ゲームサイズに縮小した際にも輪郭を残す。
GUI側の1.8倍表示と強弱・状態の色表示は維持する。

参考: [Shade3Dの輪郭線レンダリングの記事](https://knowledge.shade3d.jp/knowledgebase/%E8%BC%AA%E9%83%AD%E7%B7%9A%E3%82%92%E3%83%AC%E3%83%B3%E3%83%80%E3%83%AA%E3%83%B3%E3%82%B0%E3%81%99%E3%82%8B%EF%BC%88%E3%83%88%E3%82%A5%E3%83%BC%E3%83%B3%E3%83%AC%E3%83%B3%E3%83%80%E3%83%A9-%EF%BC%89) の「フォトリアル（エッジ付）」に相当する方向性。Shade3Dそのものは使用せず、Blenderで実現する。


## キャラクター素材の再生成

現行のキャラクター画像は `heroic/characters-angle60.blend` から書き出す。
モデルのシーンは `build-heroic.py` が生成し、`export-sprites.py` が
`src/arlq/assets/characters/` の透過PNGを作る。
旧モデル案やそのプレビューは現行の素材生成に使わない。

```bash
blender --background --threads 4 --python dev-samples/3d-stage1/build-heroic.py
blender --background --threads 4 --python dev-samples/3d-stage1/export-sprites.py
```

## 現行キャラクターモデル

`heroic/` は、ゲームで使う現行キャラクターのモデルとプレビューを保存する。
`build-heroic.py` がキャラクターを1つのシーンに作り、スプライト書き出しの中心座標も保存する。

- 共通: 背後からの寒色・暖色のリムライトと、縁が淡く光る材質。色の彩度を上げ、Standard表示で発光色の白飛びを防ぐ。
- アメーバ2種類: アメーバは空色、レアアメーバは橙色の樹脂にする（紫は毒の印象になるため変更）。膜に軽い揺らぎを付け、内部に縦長の瞳を持つ光る核と小さな気泡を追加。周囲の鈍角の円錐6つは維持する。レアアメーバの上部3つの突起は、金色に光る六角の結晶にする。
- バイソン: 肩のこぶに暗い毛の塊を少しだけ載せ（強く見えすぎないよう5個の小さめの塊）、頭を下げた突進の姿勢にする。角は外へ張り出して上へ反り、目は赤く光る。角はキメラ `c` `C` の剣と紛らわしくないよう、付け根を中心に当初の半分の大きさにしている。黒い鼻先と蹄、短い尾を追加。太りすぎに見えないよう、胴体の幅は最初の試作の9割にし、毛の塊と脚もその分内側へ寄せる（`bison()` の `slim`）。
- コモドドラゴン: 吻から尾まで1本の角ばった胴体にし、尾をS字に曲げる。脚は関節で曲げて横へ張り出し、光る金色の目、眉の突起、背の低い淡色の稜線を追加。爪は付けない。
- キメラ `c`: ステージ1で剣を落とすモンスター。小さい画面でも読めるよう、基本はライオンにして細かい造作を減らす。小さめの金色の胴体に、二重の深紅のたてがみと光る目を付け、淡く光る平たい刃の剣を口に横向きにくわえる。尾は太い緑のヘビにして背中の上へ高く持ち上げ、首元を広げたコブラ風の頭、黄色く光る目、赤い舌で目立たせる。ヤギの要素は付けない。
- 宝箱 `T`: 透明感を抑えたマホガニー色の樹脂に、金の帯・角金具・錠前とルビーを付ける。ふたをミミックと同じくらい少しだけ開け、すき間から中の金貨と金色の光を見せる（当初は後ろへ大きく開けていた）。宝箱の表示は開錠後に限られるため、開いた姿にした。ふたは底の平らな半円柱にし、開けても横から見て半円に見えるようにする（当初は円柱の下半分を箱に沈めていたため、開けると筒に見えた）。金の帯は外側だけを巻き（ふたは内側の空いた半円の輪、箱は前面と背面の板）、中身を取り出す口やふたの内側を横切らないようにする。ほかのモンスターと揃えて画面左へ30度向ける。宝に擬態した敵（正体が分かる前のミミック）も既存の表示判断どおり同じ画像になる。
- ミミック `M`（正体が分かったもの）: ゴーレムの一種として、宝箱 `T` と同じ形・同じ向きのまま、質感をゴーレムに寄せる（木の部分を黒い玄武岩、金具を灰色の石板にする。箱の広く平らな面が白っぽく光らないよう、ゴーレムより照り返しを抑える）。ふたは少しだけ開けて黒い中身を見せ、すき間の奥に琥珀色に光る丸い目を2つ置く（目玉ではなく丸い光。持ち上がったふたの縁の下から見えるよう手前寄りに置く）。錠前のルビーの代わりにゴーレムと同じ琥珀色に光るルーンを置く。`build-heroic.py` の `treasure(x, y, mimic=True)` で作る。
- ドラゴン `D`: ステージ1のボス。コモドドラゴン（実物）に寄せたくすんだオリーブ褐色の角ばった胴体（腹は黄土色、翼は茶色。当初はエメラルドだったが、仲間の緑と近いためモンスターらしい色に替えた）で首と頭を持ち上げ、尾を後ろで巻く。金の角・背の棘・爪、橙に光る目、少し開いた顎を付ける。半透明の膜を持つ翼は、縦長のマスで小さくならないよう上へ持ち上げて横幅を抑える。モデル自体を大きく作り、翼のはみ出しを許容して胴体を他のキャラクターと同程度の大きさにする。
- ノミコン `n`: 仲間。開いた状態で浮かぶ魔導書。半透明でほのかに光る緑の樹脂の表紙と背に、濃い緑の樹脂の角金具、白っぽい紙のページに水色に光るルーンの行（上から3行目は左右のページとも綴じ目寄りを、角が上下左右を向く膨らんだひし形にして、両目に見せる。ひし形は少し横長の切れ長にし、目尻（外側の角）をわずかに上げる。目の行の線はほかより少し短く、ほかの4行は同じ長さにそろえる。目にかからないよう、すぐ上と下の行は少し離す）、赤いしおり。ページを読ませるためカメラ側へ12度傾ける。
- レアキメラ `C`: ステージ2で呪いの剣を落とすモンスター。キメラ `c` の造形を使い、灰色の胴体、縁が赤く光る黒いたてがみ、骨のように白いヘビの尾と赤い目、赤く光る黒い刃の剣にする。`c` よりやや大きい。
- ファイアドレイク `F`: ステージ2のボス（ステージ4では強化された `F'`）。ドラゴン `D` の造形を使い、深紅の鱗、溶けたような橙の腹、橙に透ける翼、黒曜石の角・爪、黄色く光る目、口元の小さな残り火にする。`D` よりやや大きい。
- ゴーレム `g`: ステージ2のモンスター。白い大理石の壁と見間違えないよう、暗い玄武岩と灰色の石板のブロックで組んだ人型にする。短い脚、幅広の胴、肩の岩、太い腕と地面近くの大きな拳。胸の石板・目のスリット・拳に琥珀色に光るルーンを刻む。60度の見下ろしで胸と顔が見えるよう、上半身を腰から後ろへ反らせる（前かがみにすると胸が下を向いて隠れる）。
- エレボス `e`、レアエレボス `E`: 闇の煙が本体で、頭巾をかぶった姿の亡霊。足はなく、裾は煙の尾になって床へ流れる。体はメタボールで頭巾・胴・尾・腕を1つの滑らかな形に溶かし、雲のテクスチャで表面を揺らがせる。頭巾の開口部と目は、60度のカメラへ向くよう頭の上寄りに置く。目は吊り上がった光そのもので、レアエレボスでは長く大きく頭巾からはみ出す（長さは最初の試作の8割に調整）。紫は毒と紛らわしいため使わない。
  - `e`: 小さく丸い頭巾、藍色の半透明の煙、水色の目、短い腕。ステージ2の弱い敵（体力を吸う）。
  - `E`: ステージ4の上位種（レベルを下げる）。`e` の約1.35倍の幅。より黒く不透明な煙、高く尖った頭巾に黒曜石の角3本、ぼろ布のように裂けた裾と複数の尾、爪のある長い腕、赤い目。両手の間にひびの入った金の光輪（奪ったレベルの象徴）とその破片を浮かべる。
  - メタボールの表面は要素の半径より内側にできるため、`SIZES` は他より大きい値（`e` 1.71、`E` 1.98）で、見える幅を `e` はアメーバ程度、`E` はその約1.35倍に合わせている（どちらも最初の 1.9、2.2 から9割に縮めた）。

- プレイヤー: 当初の2等身・足なしから、エルフと並べたときに背が低すぎたため3等身に変えた。頭（高さ0.34）・円筒形の胴・脚がほぼ同じ高さで、脚の先に前への出っ張りが小さいブーツを付ける。頭は少し後ろへ傾けて（0.35ラジアン）、バイザーをカメラへ向ける。エルフのような縦の引き伸ばしはしない（試したが、元の形のほうがよかった）。画面下向きの構成は維持する。見た目は宇宙服のような半透明の結晶から甲冑風に変え、兜・胴・腕・脚を青みがかった鋼の板金にする。兜の正面は暗い鉄の面に目の窓を開け、そこだけを淡い水色に光らせる（窓は本物の兜の切れ込みより大きめにし、スプライトの大きさでも顔が読めるようにする）。頭頂には前から後ろへ走る鉄の稜線（とさか）、胴には板金の継ぎ目の細い鉄の帯を2本付ける。肩には腕の付け根を覆う大きな鉄の肩当て、肘には丸い鉄の肘当てを付ける。胴はドラム缶に見えないよう、上から見て横長の楕円にする（前後を0.72倍、`player()` の `flat`。ベルト・継ぎ目の帯・肩まわりのマントもそれに合わせる）。結晶の兜に光るバイザーと飾り、肩当て、ベルトを付け、マントを黒に近い紺色にして裾を縁取り、裾の広がりは控えめにする（当初は深紅だったが、足元の円盤でLPの減少を示す黄色・赤が目立たなくなるため変更した）。飾り・肩当て・ベルト・バックル・縁取り・剣の鍔は黒っぽい鉄。右手に鉄の短剣を低く構える（当初の光る刃から灰色の鉄に変え、長さを0.8倍にした）。頭の `@` はモデルからも取り除いた。

1番目は `heroic/characters-angle60.blend` と比較画像 `heroic/preview-angle60.png` を出力する。
2番目はゲーム用のキャラクター画像を書き出す。エルフ共通の部分（裾・胴・頭・耳・目、縦の伸ばしと頭の傾け）は `elf_figure()` にまとめ、エルフごとの部分を渡して作る。
シーンの照明は原点（奥の列の中央）に向けて置いているため、書き出しでは照明をキャラクターの位置へ一緒に移し、どのキャラクターも同じ当たり方で撮る（以前は原点から遠いキャラクターほど光が横から当たっていた）。照明を揃えた際に白く飛んだオキュラーの虹彩とノミコンのページは、光の強さと色を調整し、オキュラーの角膜（瞳に映り込みが出た）は取り除いた。比較画像は、ゲームの実際のマスに相当するタイルを敷いた床（14×5マス、明暗2種類の市松）の上に、1マスおきに（市松の明るいマスに）キャラクターを並べる。マスの大きさは、スプライトの書き出し（2.6単位で256ピクセル）とGUIの拡大率（`SPRITE_REFERENCE_PIXELS` の186ピクセルを、余白を除いたマス幅の1.8倍に描く。マス幅13ピクセルに対して余白は両側1ずつ）から、幅 1.24 単位、奥行き 2.20 単位（マスの縦横比20:13を60度の見下ろしの sin 60° で割り戻す）とする（`CELL_W`、`CELL_D`）。モデルはゲームでの大きさで作っているので、キャラクター同士やマスとの大きさの関係はゲーム内と同じになる。並びは奥からプレイヤー・ステージ1のモンスター・宝箱、仲間とエルフ、ステージ2以降のモンスター・ゴーレムの岩・強化の印（`ORDER`）。名前は各キャラクターのマスの手前に書く。広い比較画像では、原点近くに置いた面光源の光が端のキャラクターまで届かず暗くなるため、比較画像に限って各面光源を同じ向きのサン（平行光）に置き換え、全員を同じ明るさで照らす。サンの強さは原点での明るさ（光源の強さ ÷ (π × 距離²)）、光の角度は元の光源の見かけの大きさに合わせる。保存するシーンとスプライトの照明は面光源のまま変えない。比較画像のレンダリング時間は画素数より、ほのかに光るメッシュの三角形をCyclesが一つ一つ光源として扱うことで決まっていたため、比較画像に限ってこの扱いを止めている（約2.7分から約1.3分）。`-- --only n o` のように文字を並べると、指定したキャラクターだけを書き出す。

モンスター11体（`a` `A` `b` `c` `d` `D` `C` `F` `g` `e` `E`）は、正面から画面左へ30度だけ向きを変えてモデルに適用する（`MONSTER_YAW`）。プレイヤー・宝箱・仲間は正面向きのまま（ペガサスだけは横顔を見せるため45度）。

スプライトの大きさは3Dモデルの段階で決める。`build-heroic.py` の `SIZES` で各モデルをアメーバ基準の大きさに作り、メッシュへ適用する。のちにアメーバ2種類・コモドドラゴン・エレボス2種類は、最初の大きさの9割に縮めた（基準はアメーバの最初の大きさのまま）。
書き出しは全キャラクター共通で2.6単位あたり256ピクセル（撮影範囲4.6単位、453ピクセル四方）でレンダリングし、撮影の中心（足元から0.35単位上）に対して上下・左右対称に余白を切り詰める。足元は画像中心から一定のピクセル数だけ下になり、GUIはこれを `SPRITE_GROUND_OFFSET_PIXELS` として使う。
GUIは全画像を同じ倍率で描く（縮める前のアメーバの幅186ピクセルがマス幅の1.8倍、`sprite_funcs.py` の `SPRITE_REFERENCE_PIXELS`）。
ドラゴンだけ表示倍率を変える処理はなく、モデルが大きいため画像も大きくなる。外側の輪郭は従来どおり4ピクセル、部位の境目は1.5ピクセルの薄い線にして、細部が多くても線がうるさくならないようにする。サンプル数は256。

### 仲間の光の柱

仲間（`n` `o`、今後の `p` `l` も同じ）は、モンスターと区別するため薄い緑の光の柱に囲まれて表示する。
柱は画像に焼き込まず、GUIが地面の円盤と同じ楕円を底面とする、上が開いた円筒として描く（`sprite_funcs.py` の `pillar_image()` と `PILLAR_*`）。
奥の面はキャラクターの後ろ、手前の面はキャラクターの上に加算合成で重ね、側面の縁ほど明るく、上へ行くほど薄くする。
柱は仲間の画像がある場合だけ描き、色は仲間の緑（全体表示の薄表示では暗い緑、マップモードでは灰色）。足元の円盤は従来どおり。
プレイヤーに同行中の仲間は、元のGUIではプレイヤーの右隣のマスに文字で描くが、スプライト版では画像がプレイヤーと重なるため、0.6倍の大きさでプレイヤーの右肩のあたりに浮かべ、小さな柱で囲む（`FAMILIAR_*`）。
