# GA による ARLQ ソルバ設計

## 目的

カーソルキーの操作列を遺伝子とし、ARLQ のステージを遺伝的アルゴリズム（GA）でクリアする。
`--curses` の画面を自動操作するのではなく、ゲームロジックを直接呼び出して個体を評価する。

対象とする操作は上下左右の 4 方向である。

```python
MOVES = (
    (0, -1),  # 上
    (-1, 0),  # 左
    (1, 0),   # 右
    (0, 1),   # 下
)
```

## 既存コードとの接続

既存の `SimulationState` と `build_simulation()` を個体評価に利用する。
現在の `step_simulation()` は内部で移動方向を決定するため、GA 用に、指定された方向を 1 手適用する処理を分離する。

```text
build_simulation(stage, seed)
        ↓
apply_simulation_move(state, direction)
        ↓
update_entities() と既存のターン終了処理
```

描画処理、pygame、curses は GA の評価中には使用しない。

## 遺伝子表現

個体は固定長の移動列とする。初期値は `max_steps=500` 程度とし、クリアまたは飢餓死した後の遺伝子は評価しない。
固定長にすることで、交叉と突然変異を単純に保てる。

```text
個体 = [右, 右, 上, 左, ...]
```

将来、可変長が必要になった場合は、操作列の末尾への挿入・削除を突然変異として追加する。

## 評価フェーズ

評価対象はゲームの進行状況に応じて切り替える。

### フェーズ A：D/F を倒せない状態

宝箱および D/F への距離は評価しない。

- 倒せる一般モンスターへの接近
- レベルアップ
- ソードなど有用なアイテムの取得
- LP の回復
- 倒せる敵の種類が増えたこと

を評価する。

### フェーズ B：D/F を倒せる状態

モンスターの `effect == EFFECT_UNLOCK_TREASURE` を持つ D/F について、次の条件を満たした場合に倒せる状態とする。

```python
player_attack_by_level(player) >= monster.tribe.level
```

この判定は、通常のレベルだけでなく、ソードによる攻撃力補正も含む `player_attack_by_level()` を利用する。

- D/F への接近：大きく加点
- 倒せる一般モンスターへの接近：中程度に加点
- 食料、レベル、アイテム：補助的に加点

### フェーズ C：D/F 撃破後

D/F が撃破され、宝箱が解錠された後は、宝箱への接近を最優先する。

- 宝箱への接近：大きく加点
- 残り LP：小さく加点
- 行動数：小さく減点

フェーズ判定は文字 `"D"` / `"F"` に依存せず、`EFFECT_UNLOCK_TREASURE` を持つモンスターの状態で判定する。

## 距離の評価

対象エンティティの座標までの、地形上の経路距離を使う。モンスターや同行者は経路検索上の障害物としない。
実際のシミュレーションでは接触・戦闘を行うが、評価関数ではモンスターをすり抜ける経路も許容する。

壁については次の 2 モードを使う。

```text
通常モード       壁は通過不可
壁破壊モード     壁を通過可能
```

壁破壊モードは、剣を所持し使用回数が残っている場合に使う。剣の使用回数を距離計算に厳密に含めるのではなく、評価用の近似として扱い、実際の剣の消費はシミュレーション側に任せる。

壁破壊モードでは経路探索を行わず、壁とモンスターを無視したマンハッタン距離を使う。通常モードでは、経路距離が 100 以上、または到達不能な目標を無限大相当として扱う。

同一個体の評価中は、地形と壁モードが変わらない限り、目標ごとの距離マップを使い回す。
壁の破壊、カルタップの消費、岩の拡散などで地形が変化した場合はキャッシュを破棄する。

距離そのものを毎ターン加点せず、状態変化による差分を評価する。

```text
距離報酬 = 直前状態の距離 - 現在状態の距離
```

これにより、同じ場所に留まるだけの個体が過大評価されることを防ぐ。

## 一般モンスターの重み

倒せないモンスターへの接近は評価しない。倒せるモンスターについては種類に応じて重みを変える。

```text
倒せる + 食料が多い        高評価
倒せる + 有用なソード      高評価
倒せる + レベル上昇        中〜高評価
倒せるが効果が小さい       小さな評価
倒せない                   評価しない
```

既存の `entity_priority()` および `strategy_bonus()` の考え方を共通化して利用する。

## 終端評価

```text
クリア       +1,000,000
飢餓死       -10,000
```

クリア個体には、残り LP と短い操作列を反映する。

```text
クリアボーナス + 残り LP * 20 - 使用ステップ数 * 2
```

ゲーム内の死は飢餓死のみを終端条件として扱う。飢餓死個体も操作列の評価対象には残し、高レベル・装備取得・目標への接近などの遺伝子を次世代へ伝えられるようにする。リスポーン回数そのものは減点しない。リスポーンに伴う LP 減少、移動による LP 消費、追加ステップは通常の状態評価で反映される。

## 中間報酬

生存個体が LP の維持だけに収束することを防ぐため、ゲーム進行上の節目に中間報酬を与える。

```text
レベル 5 到達             +50
レベル 10 到達            +150
レベル 15 到達            +300
レベル 20 到達            +700
レベル 30 到達            +1,500
レベル 40 到達            +3,000
レベル 60 到達            +5,000
D/F を倒せる攻撃力に到達  +10,000
D/F 撃破                  +100,000
```

レベル報酬は閾値を初めて通過した時だけ加算する。D/F 撃破報酬は、`EFFECT_UNLOCK_TREASURE` を持つモンスターが存在しなくなった時に加算する。
D/F 撃破後はレベルアップおよびレベル閾値の報酬を加算せず、宝箱への接近とクリアを優先する。
クリア個体の比較では、移動ステップ数を大きく減点し、同程度のLP・成長度であれば短い経路を優先する。
クリア個体の最終評価は、クリア基礎点 `1,000,000`、クリアまでの累積ルート評価を使用ステップ数で割った値、残り LP `* 20` の合計とする。失敗個体の評価は従来どおりとする。
LP 回復の報酬は段階式とする。LP 40 までは通常の回復率、LP 40〜70 は半分の回復率、LP 70 を超える部分には報酬を与えない。実際のゲーム内 LP 上限は変更しない。

## GA パラメータ案

```text
個体数           200
世代数           500
エリート保存     上位 10 個体
親選択           トーナメント選択
交叉             2 点交叉
突然変異率       3〜5 %
セグメント移動率 5〜10 %
```

個体評価は互いに独立しているため、必要に応じて `ProcessPoolExecutor` で並列化する。
`--population` は GA の個体数、`--workers` は評価用プロセス数を表す。プロセスプールは世代をまたいで使い回す。
各世代の個体は UDLR の辞書順にソートし、連続したチャンクに分割する。各ワーカーは担当チャンク内で共通プレフィックスを一度だけ評価し、分岐時点のゲーム状態、スコア、距離キャッシュ、乱数状態を保存して再利用する。プロセス境界をまたぐ共通部分は重複評価される。

```bash
arlq-ga --stage 1 --seed 1234 --population 400 --workers 8
```

突然変異では、1 遺伝子の方向変更に加え、長さ 1〜4 の連続した操作列を切り出して別位置へ移動するセグメント移動を利用する。セグメント移動は遺伝子列の長さを維持する。
一定世代改善がなければ、突然変異率を一時的に 10〜15 % へ上げる。

## 評価手順

```text
初期集団を生成
    ↓
各個体を build_simulation() から再生
    ↓
各操作を apply_simulation_move() に渡す
    ↓
フェーズに応じて差分評価
    ↓
選択・交叉・突然変異
    ↓
終了条件まで反復
```

最初は特定シードを解くモードで検証する。

```bash
arlq-ga --stage 1 --seed 1234 --max-steps 500
```

動作確認後、複数シードで同じ個体を評価し、特定マップに依存しないソルバへ拡張する。

## 実装予定ファイル

```text
src/arlq/ga_solver.py
```

主な関数は以下とする。

```python
random_individual()
evaluate_individual(individual, stage, seed)
select_parent(population)
crossover(parent_a, parent_b)
mutate(individual)
run_ga(stage, seed, ...)
main()
```

最良個体の操作列、使用ステップ数、残り LP、クリア世代を出力し、後から通常のゲームで再生できる形式でも保存する。

## 座標ターゲット型ソルバ

操作列を直接進化させる方式とは別に、絶対座標によるターゲット列を遺伝子とする `arlq-target-ga` を用意する。

```text
遺伝子 = [(x1, y1), (x2, y2), ...]
```

各座標について、モンスターまたは宝箱を目標として選び、最小コスト経路を `u/d/l/r` 列へ変換する。同じ種類のモンスターでも座標が異なれば別の遺伝子として扱う。

評価中にモンスターがリスポーンした場合は、その座標を実行時のターゲットキューへ追加する。遺伝子本体は評価中に書き換えず、リスポーン個体は動的な補助ターゲットとして扱う。

### 座標ターゲットの評価とチェックポイント

座標ターゲット列も、直接 UDLR 列と同様に、ソートした隣接個体の共通プレフィックスを利用して評価を高速化する。

```text
個体 1 と個体 2 の共通プレフィックスを P12 とする
個体 2 と個体 3 の共通プレフィックスを P23 とする
```

個体 1 の評価中に `P12` の直後の状態を保存し、個体 2 はそこから評価を開始する。個体 2 の評価時には `P23` も先読みする。`P23` が `P12` より長ければ、個体 2 の評価途中で `P23` の状態も保存し、個体 3 がそこから再開できるようにする。`P23` が短い場合は、個体 3 を初期状態から評価する。

チェックポイントには次の情報を含める。

- ゲーム状態
- 現在位置と処理済みターゲット数
- スコア、ステップ数、移動履歴
- 動的に追加されたリスポーンターゲット
- 既に発見したリスポーンターゲットの座標
- ゲーム内乱数の状態

共通プレフィックスの後ろは個体ごとに異なるため、保存したゲーム状態を維持したまま、後続の座標列だけを新しい個体の内容に差し替える。動的なリスポーンターゲットは、指定された座標列の後ろに追加する。

この再利用は同一世代・同一ワーカープロセス・同一チャンク内に限る。ワーカープロセス間や世代間では状態を共有しない。また、座標ターゲットの経路探索は状態に依存するため、同じ座標プレフィックスからは同じ状態・同じ決定的な経路を得られることを前提とする。

```bash
arlq-target-ga --stage 1 --seed 1234 --target-length 25 --population 100 --generations 200 --workers 8
```

座標ターゲット型ソルバは、勝利個体を発見しても既定では最後の世代まで探索を続ける。勝利した中で残り LP が多く、移動数が少ない個体を改良できる。早期終了したい場合は `--stop-on-win` を指定する。

複数シードをまとめて評価する場合は `arlq-target-ga-batch` を使う。成功したシードには実際の `u/d/l/r` 操作列を、失敗したシードには空欄を書いた CSV を生成する。
`--stop-on-win` を指定すると、各シードで勝利個体を発見した時点で、そのシードの探索を終了する。

複数シードを同時に実行する場合は、シード単位の並列化を優先する。`--seed-workers` は同時に実行するシード数を表し、シード並列時は各 GA 内部の個体評価を直列化して、プロセスの二重並列化を避ける。単一シード内の個体評価を並列化したい場合は、`--seed-workers 1` のまま `--workers` を指定する。

```bash
arlq-target-ga-batch --stage 1 --seed-start 1 --seed-count 100 --output stage1-results.csv --seed-workers 6 --stop-on-win
```

GA の大量評価では、プロダクト本体とは分離した PyPy 環境を利用できる。PyPy の JIT ウォームアップを考慮し、個体評価を十分な回数繰り返す条件で CPython などと実行時間を比較する。PyPy を利用する場合も、シード単位の並列化では各プロセス内の GA 評価を直列化する。
